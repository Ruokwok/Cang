# 编译与当前限制

> 返回 [文档索引](README.md)

## 要点
- native 声明：编译器/运行时实现的函数签名
- 函数定义位置、函数对象与内存的已知限制
- 当前编译流程：lex -> parse -> 单态化 -> IR -> clang/gcc


`native` 表示只有签名、没有 Cang 函数体的声明，由编译器或运行时实现：

```cang
static native func int nativeFunction(int x)
```

标准库中的 `Math`、`System`、`Stdout` 等 API 主要使用这种方式声明，再由 LLVMGen 内建实现。

### 22.2 函数定义位置

`class` 之前允许 `namespace`、`import`、**全局函数**和注释；一个文件一个类，类体内放字段、构造方法（`init`/`_init`）与方法，逻辑语句写在 `static void main` 或方法内：

```cang
func int add(int a, int b) {      # 全局函数（class 之前）
    return a + b
}

class Main
    static func void main(String[] args) {
        Stdout.println(add(1, 2))
    }
```

### 22.3 函数对象限制

当前支持：

- 普通函数引用；
- lambda（0..N 个参数，返回类型可省略或显式，按值捕获外部变量与 `this`）；
- `this::method`（实例方法内）；
- `object::method`；
- `Class::staticMethod`。

线程块 `thread { }` 与对象式 `task()` 的任务须为无参无返回函数（可按值捕获）。

### 22.4 内存管理

Cang 默认采用 Boehm GC 自动回收：

- 数组和对象由 GC 自动回收，`System.gc()` 可手动触发；
- `free` 仍可用于提前释放（GC 模式下映射为 `GC_free`）；
- `--no-gc` 可切回纯手动模式；
- 基本类型使用栈槽位；
- 字符串字面量由常量池管理；
- 线程与 GC 已兼容，但对象/数组不允许跨线程传递，线程间异常不传播。

Cang 的编译流程大致为：

```text
.cang 源码
    ↓
Lexer 词法分析
    ↓
Parser + AST 语法分析
    ↓
标准库/import 解析
    ↓
LLVMGen 生成 LLVM IR
    ↓
.clang/.ll
    ↓
clang 生成目标文件
    ↓
gcc/链接器生成可执行文件
```

生成的 LLVM 文件可以使用：

```powershell
cang program.cang --no-link
```

查看：

```text
program.ll
```

这对于排查类型、函数调用、数组布局和平台目标问题很有帮助。
